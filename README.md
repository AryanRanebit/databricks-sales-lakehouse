# Databricks sales lakehouse (learning project)

A small data engineering pipeline built to learn how the pieces fit, not to look impressive.
It turns messy order files into a clean star schema, loads data in batches, and keeps customer history.

- **Data:** fake, generated by `data/generate_data.py` (seeded, so it is repeatable). No third-party dataset.
- **Layers:** bronze (raw), silver (cleaned), gold (star schema: `fact_sales`, `dim_customer` with SCD Type 2, `dim_product`, `dim_date`).
- **Incremental:** batch2 arrives later with new orders, status changes and customers who moved. Re-running a batch changes nothing.

## Two ways it runs
| | Local | Databricks Free Edition |
|---|---|---|
| Engine | DuckDB (`pipeline.py`, `sql/`) | Spark SQL on Delta tables (`databricks/`) |
| Tests | 8 pytest tests + 13 SQL quality checks | the same 13 checks, run in a notebook |
| Failure safety | one transaction per batch, rolls back | no multi-statement transactions, so each step is safe to retry |
| Status | tested | run in a real workspace (notebooks, no scheduled job yet) |

Both give the same counts on the fake data: 1676 clean orders, 24 rejected, 218 customer versions, 4221 fact rows.

## Run locally
```
pip install -r requirements.txt
python data/generate_data.py
pytest -q
python pipeline.py
```

## Run on Databricks Free Edition
Import the four files in `databricks/` as notebooks, run `00_setup_and_generate` once, then `30_run_pipeline`.

## What this is not
No Azure Data Factory, Synapse or ADLS, no T-SQL, no Data Vault. Databricks notebooks play the orchestration role here.
Read `docs/LEARNING.md` for the design notes and known limits.
